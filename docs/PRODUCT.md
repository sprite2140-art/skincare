# 护肤Agent 产品文档

Oct 15, 2026 · @Laura

## 产品概述

一个免费、开源的 App：用户回答自己皮肤、头皮、头发的状态和需求，它以成分为依据，直接推荐最适合的具体产品，并解释每一项评分的原因。

推荐以产品为单位，不以品牌或营销为导向；不接广告、不拿返佣，打分逻辑公开。

项目性质有三层：解决作者自己的问题；作为在 X 和小红书发布的第一个开源项目；一个不以盈利为前提的小创业项目，未来不排除被大型零售商收购或合作。

搭建方式：主要依靠 AI 工具（Claude 与 ChatGPT 协作）。

## 目标用户与痛点

目标用户是所有在美妆店或网上购买护肤品时不知道该选什么的人，不分性别、不分预算。第一批重点用户来自两个发布平台：

- 海外华人
- 海外英语用户
- 关注欧美日韩产品的国内用户

核心痛点：

- 产品太多，不知道哪个适合自己，也看不懂成分。
- 网上介绍分不清哪些是广告，筛选的时间成本很高。
- 皮肤状态会随城市、季节变化，但很少有工具考虑环境。
- 头皮和头发护理常被忽略，它们也是整体护理的一部分。

设计原则：用户很懒，必须用最简单的方式。用户不愿在店里扫码（会被店员看到，不自在），也不喜欢自拍（前置摄像头拍出来不好看，会对产品产生负面感受）。

## 产品范围

覆盖面部、头皮、头发和身体护理四个分区，排除彩妆；界面支持中文和英文。

| 分区 | 包含品类 | 阶段 |
| --- | --- | --- |
| 面部 | 卸妆、洁面、化妆水、精华、面霜、防晒、去角质 | 第一阶段 |
| 头皮 | 洗发水、头皮护理 | 第一阶段 |
| 头发 | 护发素、发膜、护发油 | 第一阶段 |
| 身体 | 沐浴露、身体乳、身体去角质 | 第二阶段 |

市场覆盖欧美、日本、韩国、中国四个市场的知名产品。

## 核心功能与使用流程

产品原则：简单地帮用户解决实际问题，同时让关心自己皮肤和头皮的人顺便学到一点东西。使用场景在“出门前”：在家拿到推荐，带着清单去店里或网购。

主流程：

1. 选关心的部位：面部 / 头皮 / 头发。
2. 选想找的品类：可以只选一个，也可以选多个；没有任何一步是必须的，不用精华、不用防晒的人不会被打扰。
3. 首次使用填基础档案和该部位的问题（约 30 秒到 1 分钟），之后不再重填。
4. 得到推荐：每个品类两三个产品，附综合分、各维度理由，以及“核心成分相似的平价选择”和两者的成分差异。

功能清单：

- 学一点：每个推荐理由就是一个小知识；点击任何成分弹出一两句通俗解释。另有可选入口“不知道从哪开始？看看基础步骤”，说明护肤和洗头的顺序，并告诉用户哪些步骤可以跳过。
- 多份档案：“我”和“帮别人测”（如男朋友、妈妈）各有一份，买东西时切换。
- 我在用的产品：第一版用搜索添加，后期加拍照识别；用于搭配冲突检查。
- 自动更新：根据城市天气自动换季；用户打开时顶部显示“换季了，你的推荐有 2 处更新”，不发推送。约每三个月在打开时轻问一次“最近有变化吗”，一键“没变化”即可。搬城市、备孕等变化由用户自己在档案里修改。
- 轻量反馈：用了两三周后一键“好用 / 没感觉 / 闷痘或过敏”，更新用户自己的“雷区成分清单”。
- 分享卡片：城市皮肤天气卡、皮肤类型卡、平替对比卡；卡片带名称和链接，不做“分享解锁”。

隐私：用户档案只存在用户自己的手机上，不上传服务器。

自拍和皮肤扫描放到后期；若加入，不显示照片本身，或只拍头皮等不涉及颜值的部位。

## 推荐逻辑

推荐分两层：输入层描述用户状态，输出层对每个产品按多个维度打分，每个维度附一句原因。

**输入层**

| 类别 | 内容 | 获取方式 |
| --- | --- | --- |
| 面部 | 肤质；出油、干燥、痘痘、泛红敏感、色沉、初老 | 用户选择 |
| 头皮 | 油、头皮屑、痒、掉发 | 用户选择 |
| 头发 | 受损、染烫、粗细、卷直 | 用户选择 |
| 环境 | 城市湿度、紫外线、水硬度、季节 | 根据城市自动获取 |
| 偏好 | 预算、无香精、质地 | 用户选择 |
| 已在用产品 | 成分表 | 第一版搜索添加，后期拍照识别 |
| 特殊状态 | 怀孕、备孕、哺乳、处方药 | 档案中单独入口，用户自选 |

**输出层（每个产品的评分维度）**

| 维度 | 含义 | 是否计入适配分 |
| --- | --- | --- |
| 需求匹配度 | 有效成分是否针对用户的困扰 | 是 |
| 证据强度 | 成分背后的研究支持强弱 | 是 |
| 刺激风险 | 香精、酒精、精油、致痘成分对该用户的风险 | 是 |
| 环境适配 | 在用户所在城市当前气候下是否合适 | 是 |
| 搭配冲突 | 与已在用产品是否有成分冲突 | 是 |
| 价格 | 筛选条件 | 否 |
| 透明度 | 是否公开浓度、成分是否完整 | 否，独立标签 |

示例输出：某款洗发水，综合适配 82 分。需求匹配高，含吡罗克酮乙醇胺盐，针对头皮屑；刺激风险中等，含香精而用户头皮易痒；环境适配高，用户所在城市水偏硬，这款含螯合剂。

知名度只决定产品能否入库，不参与打分。

## 打分算法（初稿）

综合适配分（0–100）= 需求匹配 50% + 刺激风险 25% + 证据强度 15% + 环境适配 10%。权重是初始假设，需要在朋友试用后调整。

计算分三步：

1. 硬性过滤（不打分，直接排除并说明原因）：特殊状态不适用的成分、用户填写的过敏或想避开的成分、超出预算。
2. 分维度打分（见下表），加权得到综合分。
3. 搭配检查：与已在用产品的冲突不扣分，而是显示提醒和用法建议（如“与你的 A 醇分开早晚使用”）；严重冲突则不推荐。

| 维度 | 权重 | 怎么算 |
| --- | --- | --- |
| 需求匹配 | 50% | 用户每个困扰按优先级加权（第一困扰权重最高）；产品含针对该困扰的有效成分即得分；成分位于成分表前部、或公开浓度且在有效范围内，得分更高 |
| 刺激风险 | 25% | 满分起扣：香精、酒精、精油、高浓度酸类等每项扣分；敏感肌或头皮易痒的用户扣分加倍 |
| 证据强度 | 15% | 取主要有效成分的证据等级：A 多项临床研究或指南支持；B 有限临床研究；C 仅体外或理论依据 |
| 环境适配 | 10% | 依据城市湿度、紫外线、水硬度、季节：干燥地区加分保湿成分，硬水地区加分螯合剂，高紫外线地区提示防晒 |

结果展示：综合分 + 每个维度的高 / 中 / 低和一句原因；价格和透明度作为独立标签。

打分全部用固定规则计算，不调用 AI 生成：结果稳定、成本低、开源可审查，也更容易满足中国平台对 AI 生成内容的要求。

## 问卷设计（初稿）

全部是点选题，不用打字；基础档案 5 题，每个分区 4–6 题，填完一块即可看结果。标“就医提示”的选项被选中时，结果页顶部建议看皮肤科医生。

**基础档案（所有人）**

| 问题 | 选项 | 用于 |
| --- | --- | --- |
| 你在哪个城市？ | 自动定位 / 手动输入 | 环境适配、货币 |
| 单件预算上限？ | ≤ 12 USD / ≤ 30 USD / 不限（显示时换算成当地货币） | 筛选 |
| 特殊状态（档案中单独入口，不在首次流程中出现） | 无 / 怀孕 / 备孕 / 哺乳 / 正在用处方皮肤药 | 硬性过滤 |
| 有想避开的成分吗？（可跳过） | 香精 / 酒精 / 精油 / 其他（搜索成分） | 硬性过滤 |
| 其他偏好（多选） | 纯素 / 无香精 / 无所谓 | 筛选 |

**面部**

| 问题 | 选项 | 用于 |
| --- | --- | --- |
| 洗完脸不涂东西，1 小时后感觉？ | 紧绷起皮 / 有点干 / 舒服 / T 区油 / 全脸油 | 肤质 |
| 最近最困扰你的？（最多 3 个，按重要程度排序） | 痘痘闭口 / 出油 / 干燥脱皮 / 泛红刺痛 / 暗沉色斑 / 细纹松弛 / 毛孔 | 需求匹配 |
| 皮肤容易敏感吗？ | 很少 / 换季偶尔 / 经常 | 刺激风险 |
| 痘痘情况？（选了痘痘才问） | 偶尔几颗 / 经常反复 / 大面积或有疼痛的大包（就医提示） | 需求匹配、安全 |
| 想找哪些品类？（多选） | 卸妆 / 洁面 / 化妆水 / 精华 / 面霜 / 防晒 / 去角质 | 推荐范围 |

**头皮**

| 问题 | 选项 | 用于 |

| 洗头后多久头发变油？ | 当天 / 1–2 天 / 3 天以上 | 头皮油性 |
| 头皮有哪些困扰？（多选） | 头皮屑 / 痒 / 发红 / 掉发 / 都没有 | 需求匹配 |

| --- | --- | --- |

| 日本 | @cosme、松本清、Loft | @cosme 年度大赏 |
| 韩国 | Olive Young | Olive Young Awards、品类排行 |
| 中国 | 天猫旗舰店、丝芙兰中国、屈臣氏 | 天猫品类榜 |

**同名产品不同地区配方不同。** 各国法规不同，防晒最典型：日韩和欧洲常用的一些防晒剂在美国尚未获批。数据库按“产品 + 销售地区”存配方，并标注国内能否买到。

数据来源：

- 品牌官网公开的成分表（首选，可用 AI 辅助整理）。
- Open Beauty Facts 开放数据库（可合法使用，需遵守其许可；覆盖不全）。
- 零售网站信息最全，但多数条款禁止自动抓取，开源发布抓取代码和数据风险更高，不建议。

中英成分名以 INCI 英文名和国家药监局发布的化妆品原料目录中文名为对照基础。水硬度按城市级别存储，来自各地供水部门的水质报告，作为提示项。

## 成分知识库

成分知识库是打分的地基：从产品库倒推建立，分三类对待，由 AI 起草、人工核对，只有“已核对”条目参与打分。

建法：汇总第一版所有产品的成分表，按出现频率排序，优先覆盖最常见的成分。

| 类别 | 例子 | 数量估计 | 处理方式 |
| --- | --- | --- | --- |
| 有效成分 | 烟酰胺、A 醇类、果酸、水杨酸、维 C、壬二酸、神经酰胺、吡罗克酮乙醇胺盐 | 几十到一百个 | 精细整理功效、浓度、证据 |
| 风险成分 | 香精、精油、变性乙醇、部分防腐剂 | 几十个 | 决定刺激风险分 |
| 基础成分 | 水、甘油、乳化剂 | 最多 | 按 CosIng 功能自动归类，不影响打分 |

每个成分记录：INCI 英文名、中文标准名、别名、功能、针对的困扰、有效浓度范围、证据等级（A/B/C）及来源链接、风险标签、搭配冲突、中英文通俗解释、核对状态和日期。

来源分三层：

- 监管（硬规则）：欧盟 CosIng 与 SCCS 意见、美国 FDA 与 CIR、中国《已使用化妆品原料目录》和《化妆品安全技术规范》、韩国功能性化妆品认可成分、日本医药部外品有效成分。
- 临床证据（证据强度）：PubMed、Cochrane 系统综述、AAD 等皮肤科指南。
- 专业科普（通俗解释）：AAD 公众页面、DermNet；孕期哺乳参考 LactMed、MotherToBaby。

致痘等级表多来自早年动物实验，可靠性有争议，不作为硬规则。

库里没有的产品或成分：AI 可以帮忙查找成分表，但不给出分数；未知成分如实标注“有 N 个成分暂无数据”；用户搜过但库里没有的内容自动记录，作为扩充优先清单。

审核：目前没有认识的专业人士。计划发布前私信 X 和小红书上的皮肤科医生或配方师博主，并公开邀请专业人士纠错。

## 安全边界与合规

特殊状态（怀孕、备孕、哺乳、正在用处方皮肤药）不放进必填流程，而是档案里的单独入口，用户自己选择。选择后排除不适合的产品，并说明排除原因。安全兜底：推荐的产品若含孕期需注意的成分，对所有人被动显示一行“含某某成分，孕期或哺乳期请注意”，不询问任何人。需关注成分清单必须依据权威来源整理。

医疗措辞：产品只做“评估”和“建议”，不做“诊断”。遇到严重痤疮、脂溢性皮炎、短期大量掉发等情况，引导用户看皮肤科医生。

引用与版权：

- 研究结论和事实可以用自己的话转述并标注来源；论文原文、图表不直接复制。开放获取且采用 CC-BY 等许可的论文署名即可复用。
- 成分基础数据优先用欧盟 CosIng；CIR 安全报告引用结论；AAD 引用建议并链接。
- 杂志内容受版权保护，且可能有广告合作，不作为数据来源。
- 仓库里放的数据等于“再分发”，发布前逐一核对每个数据源的使用条款。

## 开源方式

建议：代码用 MIT 许可公开在 GitHub，自己整理的产品数据用 CC BY 4.0 许可，来自第三方的数据按原许可处理。

“开源”就是把 App 的源代码公开放在 GitHub 上，并附一份许可证，说明别人可以怎么用。它和“免费 App”不冲突：App 照样上架应用商店，代码同时公开。

需要分别决定两件事：

| 对象 | 建议许可 | 含义 |
| --- | --- | --- |
| 代码 | MIT | 任何人可自由使用、修改，只需保留你的署名；最简单、最常见 |
| 自己整理的数据 | CC BY 4.0 | 别人可以用，但必须注明出处 |
| 第三方数据 | 按原许可 | 如 Open Beauty Facts 数据需遵守它自己的开放许可 |

你是代码作者，将来若与零售商合作，仍可以自己对后续版本另行授权。开源即中立性的证明：任何人都能看到打分规则是否偏向某个品牌，这也是社媒传播点。

注意：API 密钥等敏感信息绝不能提交到公开仓库。

## 分阶段路线图

第一版（v0.1）是一个网页应用，开发期内部名称为 skincare，正式名称发布前再定。策略：先用洗发水一个品类（约 20 个产品）走通全流程，验证推荐是否靠谱，再扩充其他品类。

**v0.1 包含：** 面部、头皮、头发三个分区；基础档案和特殊状态入口；选品类后的带理由推荐；点击成分看解释；平价替代；根据城市自动换季；中英文；“我”和“帮别人测”多份档案；搜索添加在用产品并检查搭配冲突；一种分享卡片；数据只存在手机本地。

**v0.1 不包含：** 拍照识别、身体护理、应用商店上架、皮肤影像评估。

技术方向：主流前端框架（如 React）做网页应用；产品库和成分库以表格文件存在 GitHub 仓库；部署到免费托管平台；天气数据用免费接口。

开发顺序：

1. 更新本文档作为开发说明。
2. 建 GitHub 仓库，并连接 Claude Code。
3. 定数据格式（产品库、成分库、城市环境）。
4. 整理洗发水的产品和相关成分。
5. 写打分逻辑。
6. 做页面。
7. 自测（作者本人和朋友）。
8. 扩充其他品类，上线并在 X 和小红书发布。

之后：v0.2 加拍照识别和更多分享卡片；v0.3 身体护理；有稳定用户后再考虑上架 App。

## 待定问题与风险

最大的风险是运营成本：免费 App 如果每次推荐都调用 AI，费用由你承担，用户越多花费越高。

建议打分用固定规则在本地计算（几乎不花钱、结果稳定、开源可审查），AI 只用于拍照识别等必须用到的地方，并设每日次数上限。

其他风险：

- 上架成本：苹果开发者账号按年收费，Google Play 一次性收费；审核对涉及健康建议的 App 可能更严。
- 数据维护：品牌常更改配方，需要定期核对；一个人维护约 900 个产品工作量大。
- 成分分析的局限：成分表看不出浓度和配方差异，分数只是参考；要避免变成“成分恐惧”工具。
- 用户隐私：特殊状态和拍摄的照片属于敏感信息，尽量只存在用户手机本地。
- 用户是否愿意回答较多问题，需要第一批朋友试用验证。

国内发布渠道：中国区 App Store 要求 ICP 备案号，申请需在中国有公司或本地发行方，短期走不通。微信小程序个人主体只开放少数类目，医疗和“深度合成”（AI 生成）类目只对非个人主体开放，且需备案；个人主体能否以“工具”类目通过尚未确认，可免费注册后在后台查看。第一版用海外托管的网页版，上线前请国内朋友实测访问；将来可考虑注册个体工商户以开放更多类目。[微信小程序开放的服务类目](https://developers.weixin.qq.com/miniprogram/product/material/) · [App Store Connect 关于中国大陆的说明](https://developer.apple.com/help/app-store-connect/reference/app-information/)

## 用 Claude + ChatGPT 协作搭建

核心原则：按模块分工，而不是两个 AI 轮流改同一个文件；两边都以同一份产品文档和同一个 GitHub 仓库为准。

| 模块 | 建议交给 | 原因 |
| --- | --- | --- |
| 整体架构、数据结构设计 | Claude | 一开始定清楚，后面所有模块都依赖它 |
| 打分规则、成分冲突规则 | Claude | 逻辑最复杂，需要稳定一致 |
| 产品成分数据整理 | ChatGPT | 量大、重复性高，按品类分批做 |
| 中英文界面文案与翻译 | ChatGPT | 独立、不影响代码 |
| 页面界面代码 | 任一方 | 按页面分，一个页面只由一方负责 |
| 代码审查 | 交叉 | 一方写的代码让另一方检查，更容易发现错误 |

省 token 的做法：

1. 写一页“背景卡”：产品一句话定位、技术选型、数据结构、命名规范。每次开新对话只贴这张卡 + 本次任务相关的文件。
2. 一个对话只做一个任务，完成后开新对话；长对话会反复消耗历史内容。
3. 改代码时要求只输出改动的部分，不要整个文件重写。
4. 每完成一步就提交到 GitHub；切换 AI 时把最新文件交给它，不依赖它“记得”。
5. AI 整理的成分表必须抽查核对品牌官网，AI 可能会编造或记错成分。

另外，Claude Code 是专门在代码仓库里直接写、改、运行代码的工具，比在聊天里复制粘贴代码更适合搭建 App，可以考虑用它做 Claude 负责的部分。
