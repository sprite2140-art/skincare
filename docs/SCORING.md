# 打分规则（v0.1 实现说明）

代码在 `src/scoring/`，参数集中在 `src/scoring/config.ts`。全部是固定规则，不调用 AI。本文是对 PRODUCT.md "打分算法（初稿）"的落地细化，所有数值都是初始假设，朋友试用后调整。

## 数据原则

- 成分匹配的来源依次为：成分库 ingredients.csv、欧盟 CosIng 批量导入（data/cosing_ingredients.csv）、欧盟香料致敏原清单。CosIng 补充的条目一律为未核对（draft）：在加香判断清单上的为风险成分（加香），其他为基础分类（base，没有 targets、没有 functions，不影响需求匹配）。规则见 DATA_SCHEMA.md。
- **CosIng 登记功能只用于展示成分解释，不直接参与打分或过滤。** 需要参与判断的功能一律通过本项目维护的清单判断：
  - 加香：香精统称、欧盟香料致敏原清单（data/eu_fragrance_allergens.csv）、加香成分清单（data/fragrance_ingredients.csv）、成分库的 essential_oil 标签；
  - 螯合剂：螯合剂清单（data/chelators.csv）。
  - 只在 CosIng 中的成分 `functions` 为空，登记功能存在 `cosingFunctions` 里，只在成分弹窗中翻译显示。`npm run validate-data` 会提示产品中"CosIng 只登记了香料功能、但不在加香清单"的成分，供人工决定是否加入清单。
  - 代码检查（2026-10-17）：原先直接用 CosIng 功能判断的有三处——加香规则 (c)、螯合剂对应"清爽洁净"、环境适配的螯合剂判断；已全部改为查清单。

- **打分**（四个维度）只用已核对的成分：`review_status = verified`，或基础成分（`category = base`，不需要人工核对）。产品成分表里带 `[待核对]` 标记的成分（名称未核对）不参与打分，显示为暂无数据。
- **测试模式**：`src/scoring/config.ts` 中的 `TEST_MODE_DRAFT_SCORING = true` 时，draft 的有效成分和风险成分也参与打分，结果页顶部说明一次"测试数据，尚未核对"（不在每张卡片上重复）。名称未核对的成分在测试模式下仍不参与打分。**正式上线前必须改为 false。**
- **安全相关**（硬性过滤、孕期提示、搭配冲突）也看 draft 成分，宁可多提示，结果中标注"成分数据未核对"。
- 不在成分库、未核对、名称未核对的成分分开统计，合并显示为"有 N 个成分暂无数据"。
- 一个产品没有任何 verified 成分时，不出分数（显示无法评分）。
- 成分名匹配前先统一写法（去掉括号俗名和 `[待核对]` 标记），匹配忽略大小写、多余空格，并同时查成分库的 aliases。规则见 DATA_SCHEMA.md "成分名称统一"。

## 第一步：硬性过滤（直接排除并说明原因）

| 条件 | 依据 |
|---|---|
| 怀孕 / 备孕 / 哺乳 | 含 `pregnancy_caution` 成分 |
| 正在用处方皮肤药 | 含 `rx_caution` 成分 |
| 想避开的具体成分 | 按名称匹配，库里没有的成分也能避开 |
| 想避开的成分类型（香精 / 酒精 / 精油） | 对应 risk_tags |
| 超出预算 | 见下方"预算"（档位或自填上限） |
| 与在用产品严重冲突 | conflicts_with 标注 `:severe` |

用户档案中填写的想避开的成分（具体成分和成分类型）都走硬性过滤，直接排除。

另外，含 `pregnancy_caution` 成分的产品对所有人被动显示"孕期或哺乳期请注意（谨慎提示，不代表确定有害）"。孕期 / 处方药相关的排除原因和提示都会附上该成分在成分库中的通俗解释，说明为什么谨慎处理（例如吡硫鎓锌：欧盟自 2022 年起以生殖毒性分类禁止用于化妆品，美国目前仍批准其作为非处方去屑成分）。

### 预算

- 预算题按品类提供三个价格上限（产品价格的 25% / 50% / 75% 分位数，显示为"$X 以内"）和不限，每档包含更便宜的产品，不起名字。上限由产品库价格（统一换算成 USD）自动计算，规则见 DATA_SCHEMA.md "预算价格上限"，代码在 `src/scoring/budget.ts`。
- 超过所选上限的产品直接排除（等于上限保留），原因写"超出你选的预算上限"。
- 价格未知或汇率表没有该币种：不参与分位数计算；选了任一上限时排除（说明"只在预算选'不限'时显示"），选"不限"时正常显示。
- 该品类有价格的产品少于 3 个：没有价格上限选项，不排除，只提示"未做预算筛选"。
- 自填上限：按用户所在地货币换算成 USD 后比较。按整套设预算时，单品不按档位筛选，总价在搭配时检查。

## 第二步：四个维度

| 维度 | 权重 | 规则 |
|---|---|---|
| 需求匹配 | 50% | **需求只来自用户明确选择的头皮困扰和期望效果，每个选项一个需求**（`NeedSpec`，问卷在 `scalpNeeds` / `hairNeeds` 中生成）：头皮困扰包括"容易出油"（scalp_oil）和"头皮敏感、容易刺激"（sensitive_scalp）；期望效果包括"修护受损"（damage）、"护色"（color_fade，这两项与去黄 / 去橙一样只在染或烫漂时出现）和"去除造型产品残留"（buildup，只在造型产品每周 3 次以上时出现，只分配给洗发水）。发丝状态、出油时间、头皮屑类型、发红、瘙痒分数、用后不适、造型产品频率等题目不推导需求。一个选项对应多个 targets 时（"柔顺"→ 毛躁、打结），按其中依据最好的一个计分。每个需求按最可靠的依据计分，见下方"效果依据"；得分 = Σ(需求权重 × 计分比例) / 总权重 × 100。洗发水侧重头皮与清洁：头皮困扰权重 2（`SHAMPOO_SCALP_WEIGHT`）；清爽洁净、蓬松、去黄、去橙、去除造型产品残留（`SHAMPOO_OWN_HAIR_TARGETS`）权重 1；其余期望效果（柔顺、滋润、减少毛躁、光泽、卷度清晰、修护受损、护色）**选洗护搭配时只分配给护发素，洗发水不匹配；只买洗发水时仍参与，权重 0.5**（`SHAMPOO_HAIR_EFFECT_WEIGHT`）。"帮我判断"建议洗发水 + 护发素时按洗护搭配处理。护发素等发丝产品只看期望效果。面部困扰有排序，按 3/2/1 加权。成分在成分表中的位置不影响得分（去屑等有效成分通常含量约 1%，排在成分表后部）。产品表没有浓度字段，暂不做浓度加分 |
| 刺激风险 | 25% | 从 100 分起扣：fragrance、alcohol、essential_oil、strong_acid、sensitizer 每个标签扣 15 分（同一标签只扣一次）；每天洗头时 strong_cleanser 扣 15 分（常用造型产品、每周 3 次以上的用户不扣）。敏感肌或头皮易痒扣分加倍；冲洗型产品（usage_type = rinse_off，品类默认值和逐个填写的规则见 DATA_SCHEMA.md）扣分减半，免洗型不变；使用方式未知时按免洗处理。两者可以叠加，例如敏感用户用洗发水：15 × 2 × 0.5 = 15。最低 0 分 |
| 证据强度 | 15% | 每个困扰取最强的依据：有成品测试记 100；否则取针对它的成分中证据最强的一个（A=100、B=70、C=40，C 级在页面上显示为"证据弱"）。**没有可评级证据的需求（只有品牌宣称、资料分类、尚无证据等级的成分，或没有依据）按最低等级 C（40 分，`MISSING_EVIDENCE_LEVEL`）计分**，页面写"暂无证据，按最低等级（C 级，40 分）计"，与有证据的需求用同一种写法和同一种表格行。再按需求权重平均。只有没选任何需求时这个维度才不计分 |
| 环境适配 | 10% | 城市水硬度由 water_hardness.csv 的分区记录汇总。**只有硬水或很硬的城市才计分**：含螯合剂（在 data/chelators.csv 清单上）记 100，不含记 50。未设城市、城市数据未核对（测试模式下 draft 也用）、水硬度未知、因供水分区而异（varies）或水质不硬时，这个维度显示"不计分"并注明原因，其余维度权重重新归一化（不再记中性 50）。湿度、紫外线、季节等接入天气接口后补充 |

- 用户没选需求、或对用户不适用（如水质不硬、未设城市）的维度不计分，其余维度的权重重新归一化。
- 例：未设城市、只有资料分类支持需求时，总分 = (需求 × 50% + 刺激 × 25% + 40 × 15%) / 90%。没有选任何需求时总分只反映刺激风险。
- 每个维度输出 0–100 分、高 / 中 / 低（≥70 / 40–69 / <40）和一句中英文原因。刺激风险维度分数高表示风险低。卡片的"评分明细"折叠在详情最后一层：每个维度显示得分、实际权重（重新归一化后的值）和对总分的贡献，最后一行为总分；不计分的维度与计分的维度行结构相同、数字列显示"—"并灰显，原因写在表格下方的说明里；并说明适合等级与分数的对应关系。
- 卡片上只显示适合等级：很适合（≥70）/ 适合（40–69）/ 一般（<40），分数数字放在"评分明细"折叠里。
- **适合等级上限**：一项需求都没有"满足"（满足 = 有主打有效成分或成品测试，计分比例 1；只有"部分"或"无依据"）的产品，适合等级最高为"一般"，不论总分多少（`ProductScore.fitCapped`，评分明细里注明）。排序按调整后的等级。
- 洗发水的需求对照分两组：头皮与清洁（头皮困扰，以及清爽洁净、蓬松、去黄、去橙、去除造型产品残留）、发丝效果（主要看护发素，权重 0.5）。发丝效果没有依据时页面写"主要看护发素"，不写"无依据"，也不计入"无依据"的数量；计分不变。只买护发素时不分组。零售商评分只展示，不参与任何计算；卡片收起时只显示评价数最多的平台，不跨平台平均。
- 推荐理由带依据类型（`Reason.basis`：tested 成品测试 / ingredients 成分表 / brand_claim 品牌宣称 / classification 资料分类），详情里显示为小标签。温和理由：刺激风险满分且不含香精时写"不含香精和常见刺激成分"，否则写"常见刺激成分少"。

### 效果依据

依据分三类，可靠程度从高到低（参数在 `src/scoring/config.ts`）：

| 依据 | 来源 | 需求匹配计分 |
|---|---|---|
| 可靠的成品测试 | products.csv 的 tested_claims（必须有来源链接；目前没有数据） | 1 |
| 品牌宣称 | brand_claim_targets（品牌产品页明确宣称的效果，按对应表从原文整理） | 0.7 |
| 产品定位 | claimed_benefits。claim_source = brand_text（品牌原文）时显示"品牌宣称"，data_classification（资料整理时的分类）时显示"资料分类"；目前的数据全部是资料分类 | 0.7（两种来源相同） |
| 品牌宣称的主打成分 | key_actives（品牌原文）对应到成分表 | 1 |
| 成分功能 | 成分库 targets；螯合剂清单上的成分对应"产品残留"（`CHELATOR_TARGETS`；用户在期望效果中选"去除造型产品残留"时才有这项需求，螯合剂另用于硬水的环境适配）。螯合剂不对应"清爽洁净" | 只有非主打成分覆盖：0.3 |

- 同一困扰取最高的一项，**不按成分数量加分**；成分功能只做辅助匹配。
- 理由和说明只写依据，不推断实际柔顺程度、光泽或留香时长。
- 产品还没填写 key_actives 时，暂按所有有效成分满分计算，并提示"未填写主打有效成分"；填了 `Not separately disclosed` 时，有效成分都按非主打计。

### 香味与"无香优先"

代码在 `src/scoring/fragrance.ts`。安全相关，draft 成分也算。

- 加香成分只限：(a) 香精统称 Parfum / Fragrance / Aroma / Flavor；(b) 欧盟香料致敏原；(c) 本项目的加香成分清单 data/fragrance_ingredients.csv（目前 12 个，由"CosIng 只登记了香料功能"的成分核对后列入）；(d) 精油。规则见 DATA_SCHEMA.md。甘油、柠檬酸、咖啡因等登记了香料功能但还有其他功能的成分不算加香。详情分开列出"欧盟需标注的香料致敏原""加香清单上的成分""其他加香成分"和精油。
- 状态：标注无香（fragrance_free_claim = yes）且未发现加香成分 / 未标注无香但未发现加香成分 / 含加香成分。标了无香但成分表里有香精的，按含加香成分处理。
- 不在成分库或名称未核对的成分无法判断，在理由和详情中写明"另有 N 个成分暂无数据，无法完全确认"，并说明"不能保证不含致敏原"。
- 香味层级：无香（"标注无香"和"成分表中未发现加香成分"合为同一层级，卡片上分别标注）→ 只含精油 → 含加香成分。用户选"无香优先"时在适合等级之后、综合分之前按此层级排序（见下方"排序"）。只是排序，不排除；想排除香精请在"想避开的成分"中选。
- 用户选了"香味好闻"时，含香精的产品理由写"气味和留香因人而异，需要自己试"，不据成分推断气味。

### 推荐理由

代码在 `src/scoring/reasons.ts`。每款最多两条：第一条是权重 × 计分最高的困扰及其依据；第二条依次取：无香优先时的香味情况 → "香味好闻"时的加香说明 → 第二个困扰 → 刺激风险低 → 硬水且含螯合剂。

## 洗护搭配

代码在 `src/scoring/routine.ts`。

- 从洗发水、护发素可推荐的产品中选一组，不限定同品牌；按整套设预算时，在总价不超过预算的组合中，先比适合等级（各单品相加，已含"一项需求都没满足时最高为一般"的上限），再比总分，同分取总价低的，与单品列表的排序一致。设了整套预算时，价格未知的产品不参与组合。
- 用户可以移除或替换单品，总价实时重新计算；替换后超出预算时提示。
- 某品类没有数据时（目前护发素），该位置显示"护发素数据整理中"，洗发水正常推荐。
- 没有符合预算或筛选条件的商品或组合时明确提示，**不自动放宽条件**。

## 第三步：搭配检查

- 一般冲突不扣分，显示提醒："建议分开早晚使用"。
- 严重冲突不推荐（见第一步）。
- 冲突关系在任一方成分的 conflicts_with 中写明即可，双向识别。

## 按市场筛选

代码在 `src/scoring/market.ts`。同一款产品在不同地区有不同配方：

- 第一阶段聚焦美国用户（含美国华人），默认市场为美国（`DEFAULT_MARKET`）。档案中选了日本、韩国、中国的城市时，默认市场取该城市的国家；没选城市或国家不在这四个市场时用美国。日本、韩国、中国的数据保留，但暂不作为重点。
- 默认市场为中国时，同时显示 `available_in_cn` 为 yes 或 cross_border 的进口版本。
- 结果页有开关"显示其他地区版本（N 个）"，打开后显示全部，其他地区的版本在卡片上标注。
- 不新增问卷题。

## 证据缺失

需求只有品牌宣称、资料分类、尚无证据等级的成分（或没有依据）时，证据强度按最低等级 C（40 分）计分，不再单独封顶总分（2026-10-19 起）。效果上与原来的"总分上限按 C 级计算"相同：缺证据的产品最多与 C 级证据产品打平，不反超。

## 排序

结果分四组，依次为：

1. **推荐列表**：可推荐的产品。
2. **不太匹配**：用户选了需求，但需求匹配为 0（没有任何依据）的产品，折叠显示在推荐列表之后，不参与洗护搭配。
3. 无法评分的产品。
4. 被排除的产品（附排除原因）。

推荐列表内的排序：

- **用户选了需求**：适合等级（按综合分：高 ≥70 / 中 40–69 / 低 <40；一项需求都没满足时最高为低）→ 香味层级（只在"无香优先"时）→ 综合分。
- **用户没有选任何需求**：不显示总分和适合等级，卡片显示"温和度 高 / 中 / 低"（刺激风险维度的等级），按温和程度（刺激风险分）从高到低、同分按价格从低到高排序；结果页顶部说明"你没有选择具体需求，以下按温和程度和价格排序"。

结果页的"价格"排序只改变推荐列表和不太匹配区域内的顺序，不改变分组。

## 问卷映射与就医提示

题目、选项、映射和就医提示的触发条件见 [QUIZ.md](QUIZ.md)，代码在 `src/profile/questionnaire.ts`。严重程度不加权，只用于就医提示和判断是否属于敏感头皮；敏感头皮（选了"头皮敏感、容易刺激"，或瘙痒 ≥ 4 分、用后不适、经常发红）刺激风险扣分加倍；只有选了"头皮敏感"才是需求（2026-10-19 起，推导出的需求不计分、不显示）。头皮发红不匹配产品，只用于判断敏感头皮和就医提示。就医提示统一措辞"建议找皮肤科医生看看"，不出现具体病名，有提示时仍然给出产品推荐。
