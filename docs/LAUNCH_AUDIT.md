## 1. 推荐结果：问卷组合遍历

脚本 `scripts/launch-audit-sweep.ts`（`npm run launch-audit-sweep`），结果全文在 `docs/launch_audit_sweep.json`。用的是结果页同样的函数，美国市场：

- **护肤**：困扰 64 种（不选，以及 7 个困扰的 1—3 项组合）× 敏感 3 档 × 特殊状态 6 种 × 预算 4 档（三档价格上限和不限），共 4,608 套流程。看每一步"可推荐"的款数，即结果页列出的首选加备选的来源，不含排除、无法评分、防晒信息不全、不太匹配的产品。肤质只影响同等级内的排序，不影响能否推荐，所以没有作为变量；选了痘痘时痘痘程度按"偶尔"。
- **洗护**：头皮困扰 22 种（不选，以及 6 个困扰的 1—2 项组合）× 期望效果 13 种（不选或 1 项；去黄、去橙、修护、护色同时选"染发"）× 特殊状态 6 种 × 预算 4 档，洗发水和护发素分别统计，共 13,728 个列表。看单品列表主列表的款数（不含排除、无法评分、"不太匹配"）。

少于 3 款的共 2,137 个（为空 628 个），全部集中在下面几种情况。特殊状态和敏感程度除了表中注明的以外都不影响结果，所以表里不再展开。

说明：
- "最低档预算"指各品类价格的第一个四分位上限（如洁面 $15.49、保湿 $14.37、去角质 $13.50，见 COVERAGE.md 和 validate-data 的输出）。

- **护肤最低档预算**：洁面、保湿、去角质是流程里的步骤，推荐太少会让"备选 2 款"不满，去角质还会显示"没有符合条件的产品"。需要补充低价产品，或者在推荐不足时提示可以放宽预算。
- 不足 3 款但不为空的情况，页面照常显示，只是备选少于 2 款。


## 2. 安全规则

测试文件 `src/scoring/launchSafety.test.ts`，用真实数据跑一组问卷答案：
- 护肤：特殊状态 6 种（无、怀孕、备孕、哺乳、处方外用药、口服异维 A 酸）× 困扰 11 组 × 敏感 2 档 × 预算 2 档，收集每步所有可推荐的产品（含首选、备选）；
- 洗护：特殊状态 6 种 × 头皮困扰 5 组，收集洗发水、护发素主列表的产品。

| # | 规则 | 结果 |
|---|---|---|
| 1 | 防晒步骤里没有 SPF 低于 30 或不是广谱的产品 | ✅ 通过 |
| 2 | 没有儿童 / 婴儿产品（subtype = kids） | ✅ 通过 |
| 3 | 没有入库依据待补的产品（含成分表为空的） | ✅ 通过 |
| 4a | 怀孕 / 备孕 / 哺乳：没有含 pregnancy_note = avoid 成分的产品；护肤没有含 A 醇类的产品 | ✅ 通过 |
| 4b | 口服异维 A 酸：免洗产品不含 A 醇类、过氧化苯甲酰、果酸、水杨酸，且没有点涂步骤；处方外用药：除过氧化苯甲酰外同样排除 | ✅ 通过 |
| 5a | 缺货链接不作为主购买按钮 | ✅ 通过 |
| 5b | 所有购买链接都缺货的产品不作为某一步的首选 | ✅ 通过（唯一这样的产品 SU-US-034 入库依据待补，本来就不推荐） |

另有一条检查确认上面这些组合确实产生了足够多的推荐（护肤 > 1,000 条、洗护 > 500 条），避免规则因为没有结果而"通过"。

说明：
- 规则 4a 的"应排除成分"按成分库的 pregnancy_note = avoid 和面部 A 醇类判断，与打分代码用的是同一份数据；成分库本身的判断是否完整不在这次审计范围内。
- 5b 目前是靠"入库依据待补"间接满足的：打分代码本身不看库存，如果以后有一款入库依据齐全、但所有链接都缺货的产品，它仍可能成为首选（见第 3 节）。

## 3. 数据完整性

可推荐的产品共 318 款（美国市场、入库依据齐全、不是儿童产品、防晒达标）。

| 检查 | 结果 |
|---|---|
| 有成分表 | 318 / 318 |
| 有价格 | 318 / 318 |
| 至少一个可用的购买链接 | 314 / 318：SE-US-005、006、007、008 没有（见下） |
| 至少一个库存正常的购买链接 | 313 / 318：另有 SU-US-032 只有一个库存未确认的品牌官网链接 |

**SE-US-005—008（Good Molecules 精华 4 款）**：purchase_links 里只有品牌官网 v1 旧版页面，品牌宣称状态为 version_mismatch（2026-10-26 作者决定：官网卖的版本与打分用的成分表不同）。按规则这时不列出品牌官网链接，所以卡片上没有购买按钮。处理方式二选一：补一个在售版本与成分表一致的零售商链接；或在补上之前不推荐这 4 款。

**链接请求**：`npm run launch-audit-links` 对 572 个不同的购买链接（purchase_links.csv 和 products.csv 的 purchase_url）逐个用 GET 请求，结果写在 `docs/launch_audit_links.json`。本次在云端环境运行，网络代理拒绝连接所有零售商和品牌网站（`CONNECT tunnel failed, response 403`），572 个都没有发出请求，记为"本环境代理不允许"。所以**这一项没有结果**，不能说明链接有效或失效。需要在能访问这些网站的环境（本地电脑，或放开网络限制的云端环境）重新运行；脚本会把结果分为正常、404 / 410、被网站拦截（401 / 403 / 405 / 429 / 503，零售商常拦截脚本）和其他错误。

## 4. 界面

截图在 `docs/screenshots/launch/`，390px 宽度、2 倍分辨率，中英文各 7 张：首页、洗护问卷、护肤问卷、护肤结果页、洗护结果页、展开的产品卡、关于页。固定档案：纽约；洗护都买、头皮屑、期望柔顺；护肤混合肌、偶尔敏感、痘痘 + 细纹。每页的可见文字一并存为 `text-<语言>-<页面>.txt`。用 `node scripts/launch-screens.mjs docs/screenshots/launch` 重新生成（先 `npm run build && npx vite preview --port 4185`）。

另外检查了首页、两个问卷、两个结果页、关于、数据说明、档案共 8 个页面在 390px 下是否横向溢出：中英文都没有。

**英文界面里的中文**：只有右上角的语言切换"中文"（有意保留）。

**中文界面里未翻译的英文和内部字段名**：
- 没有出现内部字段名（形如 `xxx_yyy` 或 `card.xxx`）。
- "US 市场"（两个结果页的标签）：`results.marketTag` 把地区代码 US 直接填进"{market} 市场"。英文界面"US market"没有问题。→ 应修
- "Ulta Best Sellers 2026"（洗护结果页的奖项标签）：奖项名按数据原文显示，窄屏下被截断成"Ulta Best Sellers 2…"。→ 可延后
- 其他英文都是专有名词，不需要翻译：品牌名和英文产品名、成分 INCI 名、零售商名（Target、Ulta）、站名 skincare、语言切换 English、AAD（问卷里注明了"美国皮肤科学会"）、关于页的 AI、Cookie、Cloudflare Pages、IP。

**其他观察**：
- 洗护搭配的"替换为"下拉框在 390px 下产品名被截断。→ 可延后
- 护肤结果页顶部只有档案名、市场和"修改问卷"，没有城市标签；洗护结果页有。→ 可延后
