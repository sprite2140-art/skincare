# 设计自查清单

每个改动界面的 PR 都要按本清单执行：用固定案例截图，存到 `docs/screenshots/<日期>-qa/`，并在 PR 说明里逐项打勾。哪一项没通过，就在 PR 说明里写明原因和后续计划。

## 固定案例

案例定义在 `src/pages/DesignQA.tsx` 的 `QA_CASES` 中，页面地址是 `/qa`（不在导航里）；`/qa?open=1` 会展开全部卡片和评分明细。产品和档案都是固定的；数据更新后，如果某个案例不再符合描述（比如产品补了证据），就在 `QA_CASES` 里换一个产品，并在 PR 说明里注明。

## 截图矩阵

每个案例都要截以下 8 种组合，8 个案例共 64 张：

- 宽度：390px、1280px
- 语言：中文、英文
- 状态：收起、展开

文件名格式为 `{案例}-{宽度}-{语言}-{状态}.png`，例如 `partial-390-zh-expanded.png`。

## 操作步骤

1. 构建并启动预览：`npm run build && npx vite preview --port 4185`。
2. 临时安装 `npm i --no-save playwright-core`，然后运行：
   `node scripts/design-qa.mjs docs/screenshots/<日期>-qa`
   如果需要指定浏览器路径，设置环境变量 `CHROMIUM_PATH`。
3. 脚本会截下全部 64 张图，并自动检查下列项目。有问题时，脚本列出问题并以非 0 状态退出。
   - 页面是否横向溢出
   - 最小字号是否小于 13px
   - 是否出现连续两个冒号
   - 中文界面中英文、数字之间是否缺空格
   - 是否出现形如 `xxx_yyy` 的字段名
   - 评分明细的维度名是否折行
4. 逐张看截图，对照下方检查项。自动检查只覆盖其中一部分。
5. 提交前压缩截图：`convert in.png -strip -colors 256 PNG8:out.png`。
6. 把下方检查项复制到 PR 说明里逐项打勾，并附上截图目录的链接。

## 检查项

- [ ] 同类信息用同一种组件和样式。例如：需求对照和评分明细用同一种表格；收起和展开的列表样式相同。
- [ ] 状态的颜色和文字一一对应：满足 = 绿，部分 = 橙，无依据 = 灰。不是状态的说明（如"主要看护发素"）用正文颜色。
- [ ] 标签结论与详情不矛盾。例如：适合等级与需求对照一致；一项需求都没满足的产品最高为"一般"；"无香"标签与成分表一致。
- [ ] 同一信息不重复出现。例如：展开后不再重复收起状态的理由；展开后零售商评分只在"在哪买"里出现；同系列名不重复品牌名。
- [ ] 窄屏下不折断词语：中文词、英文单词、维度名、按钮文字都不在中间断开。
- [ ] 中英文混排有空格；中文界面没有未翻译的地名和词（城市名用中文）。
- [ ] 空数据写法统一：表格里写"—"，句子里写"暂无……"，原因放在表格下方的说明里。
- [ ] 页面上没有内部术语（字段名、枚举值、代码里的 ID）。
